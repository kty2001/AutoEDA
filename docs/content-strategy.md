- 작성일: 2026-08-15
- 전제: [`preinvestigation.md §11`](./preinvestigation.md) 수익화 타당성 검토, [`direction.md §3`](./direction.md) 차별화 축 6
- 목적: 지식 베이스 콘텐츠의 범위·구조·우선순위를 정의하고, 광고·색인 정책과 AdSense 신청 조건을 명시함

## 1. 전략 요지

**도구는 제품, 사이트는 리소스.** 콘텐츠는 세 가지 역할을 동시에 수행함.

| 역할 | 설명 |
|---|---|
| 획득 채널 | 검색 유입 경로. 1차 타깃(입문자)은 "다중공선성 뜻"을 검색하지 사이트명을 검색하지 않음 |
| 제품 기능 | Finding 해석의 근거 문서. 축 1(발견 단위 정리)을 완성시킴 |
| 심사 요건 | AdSense가 평가할 편집 콘텐츠. 순수 도구 사이트 거절 리스크를 해소함 |

**핵심 전제**: 콘텐츠는 추가 부담이 아니라 **이미 필요한 산출물의 재배치**임. 축 1을 구현하려면 각 Finding 유형의 해설 문구를 어차피 작성해야 함. 이를 툴팁으로만 소비하지 않고 독립 문서로 발행함.

## 2. 콘텐츠 인벤토리

해설 22편 + 사례 리포트 6편. 각 해설은 800~1,200자 이상, 하나의 Finding 유형에 1:1 대응함.

### 2.1 데이터 품질군 (6편)

| # | 문서 | 대응 Finding |
|---|---|---|
| Q1 | 결측치 유형(MCAR·MAR·MNAR)과 판별 방법 | 결측률 경고 |
| Q2 | 결측 대치 방법 선택 — 평균 대치가 분포를 왜곡하는 이유 | 결측 대치 권고 |
| Q3 | 중복 행 — 완전 중복과 키 중복의 구분 | 중복 행 경고 |
| Q4 | 상수·준상수 컬럼이 분석에 미치는 영향 | 상수 컬럼 경고 |
| Q5 | 고카디널리티 범주형 변수 다루기 | 고카디널리티 경고 |
| Q6 | ID성 컬럼 식별 — 분석에서 제외해야 하는 변수 | ID 컬럼 탐지 |

### 2.2 분포군 (5편)

| # | 문서 | 대응 Finding |
|---|---|---|
| D1 | 왜도(Skewness) 해석과 로그·Box-Cox 변환 | 편포 경고 |
| D2 | 첨도(Kurtosis)가 알려주는 것 | 분포 형태 |
| D3 | 이상치 탐지법 비교 — IQR vs z-score vs 로버스트 지표 | 이상치율 |
| D4 | 이상치를 제거해야 하는가 — 판단 기준 | 이상치 조치 권고 |
| D5 | 히스토그램 구간 수(binning)가 해석을 바꾸는 경우 | 분포 시각화 |

### 2.3 관계군 (5편)

| # | 문서 | 대응 Finding |
|---|---|---|
| R1 | Pearson·Spearman·Kendall 상관계수 선택 기준 | 상관 분석 |
| R2 | 다중공선성 — VIF와 상관계수로 진단하기 | 높은 상관 쌍 경고 |
| R3 | 상관관계와 인과관계를 혼동하지 않는 방법 | 상관 해석 |
| R4 | 범주형-수치형 관계 측정 (ANOVA·상관비) | 혼합형 관계 |
| R5 | 데이터 누수(Data Leakage) 후보 탐지 | 타깃 고상관 경고 |

### 2.4 타깃·모델링군 (3편)

| # | 문서 | 대응 Finding |
|---|---|---|
| T1 | 클래스 불균형 — 정확도를 쓰면 안 되는 이유와 지표 선택 | 클래스 불균형 경고 |
| T2 | 타깃 분포가 회귀 모델에 미치는 영향 | 타깃 편포 |
| T3 | 스케일링이 필요한 경우와 불필요한 경우 | 스케일 차이 경고 |

### 2.5 프로세스·한국 데이터 환경군 (3편) — **우선 작성**

| # | 문서 | 비고 |
|---|---|---|
| K1 | EDA 진행 순서 체크리스트 | `direction.md` 축 2의 STEP 흐름을 문서화. 사이트 성격을 설명하는 허브 문서 |
| K2 | CSV 인코딩 오류(CP949·EUC-KR·UTF-8) 진단과 해결 | 국내 검색 수요 있고 영문 경쟁 무의미 |
| K3 | 한국 공공데이터 전처리에서 자주 만나는 함정 | 병합 셀, 소계 행, 단위 혼재, 한글 컬럼명 |

이 3편은 영문 자료로 대체 불가하므로 information gain이 가장 높음. **가장 먼저 작성함.**

### 2.6 사례 리포트 (6편)

실제 데이터를 분석해 Finding과 해석까지 제시하는 완성형 문서. 업로드·로그인 없이 결과를 볼 수 있는 **데모 역할**을 겸함.

| # | 데이터셋 | 목적 |
|---|---|---|
| C1 | Titanic | 이진 분류 타깃 EDA 예시, 클래스 불균형·결측 처리 |
| C2 | House Price | 회귀 타깃 EDA 예시, 편포·다중공선성 |
| C3~C6 | 국내 공공데이터 3~4건 | 한국 데이터 환경 실증. K2·K3와 상호 링크 |

> **주의**: 사례 리포트를 자동 생성으로 대량 발행하면 programmatic pages(scaled content farming)로 판정되어 역효과임. 소수를 손으로 깊게 작성함. 자동 생성 결과를 그대로 발행하지 않음.

## 3. 도구 ↔ 콘텐츠 연결 구조

```text
검색 유입 → 해설 페이지 → [내 데이터로 확인하기] → 도구 → 분석 결과
                ▲                                            │
                └────────── Finding의 [자세히] 링크 ◀─────────┘
                │                                            ▲
                └── 뒤로가기 → sessionStorage로 결과 복원 ────┘
                                    │
                              공개 사례 리포트
                        (파일 선택 없이 결과 미리보기)
```

이 왕복이 성립하려면 해설을 보고 돌아왔을 때 결과가 살아 있어야 함. 백엔드가 없으므로 통계 JSON을 sessionStorage에 캐시해 해결하며, 이는 편의 기능이 아니라 **기능 요건**임 ([`screens.md §5`](./screens.md)).

**연결 규칙**

1. 모든 Finding 유형은 대응 해설 페이지를 1:1로 가짐 (§2 표의 "대응 Finding" 열)
2. 결과 화면의 각 Finding에 `자세히` 링크 → 해당 해설 페이지
3. 해설 페이지 하단에 `내 데이터로 확인하기` CTA → 업로드 화면
4. 해설 페이지 하단에 해당 Finding이 실제로 등장하는 사례 리포트 링크
5. K1(EDA 진행 순서 체크리스트)이 허브 문서로서 전체 해설을 군별로 링크함 (hub-and-spoke)

**도구 페이지 자체의 콘텐츠**: 업로드 화면에도 도구 설명·처리 방식·지원 형식·크기 제한·한계·FAQ를 배치함. 인터페이스만 있는 페이지를 만들지 않음.

## 4. 광고 배치 및 색인 정책

| 페이지 | 광고 | 색인 | sitemap |
|---|:---:|:---:|:---:|
| 랜딩 | ○ | ○ | ○ |
| 해설 페이지 / 용어집 | ○ | ○ | ○ |
| 공개 사례 리포트 | ○ | ○ | ○ |
| 도구 화면 (진행·결과 상태 포함) | × | ○ | ○ |
| **소개 / 문의 / 개인정보처리방침 / 이용약관** | × | **× (`noindex, follow`)** | × |

**근거 3가지**

1. **결과** — 도구가 단일 페이지 4상태 구조라 결과에는 별도 URL이 없음([`screens.md §4`](./screens.md)). **초기 HTML에 결과 UI를 두지 않으므로** `noindex` 없이도 결과가 색인되지 않고, 색인되는 것은 도구 설명·FAQ뿐임. 광고를 제외해 UGC 정책 준수 책임과 심사 리스크를 회피함
2. **정책 페이지 4종을 색인에서 뺀다** — 심사자 눈에는 보일러플레이트이고, 색인 코퍼스를 차지하면 감점 요인임. 실측 사례에서 색인 12건 중 5건(약 27%)이 이 부류였던 것이 거절 사유로 지목됨. **있어야 하지만 코퍼스에는 들어가지 않게 함.** 푸터 링크는 `follow`로 남겨 크롤러·심사자가 도달할 경로를 유지함
3. **분석 흐름 중간에 광고를 넣지 않음** — 도구 UX를 훼손하지 않음

> **`noindex`와 `robots.txt` Disallow를 병용하지 않음.** 크롤이 막히면 Googlebot이 `noindex` 메타를 읽지 못해 오히려 색인이 남을 수 있음. 둘 중 하나만 씀.

## 5. 필수 페이지 (4종)

| 페이지 | 필수 기재 사항 |
|---|---|
| 소개 | 서비스 목적, 운영 주체, 분석 방법론 및 사용 라이브러리 |
| 문의 | 동작하는 이메일 주소 또는 문의 폼 |
| 개인정보처리방침 | 업로드 데이터의 취급 범위, 보존 기간, 삭제 방법, 제3자 전송 여부, 쿠키 사용, 개인화 광고 고지 |
| 이용약관 | 서비스 제공 범위, 분석 결과의 정확성에 대한 면책, 금지 행위 |

개인정보처리방침은 AdSense 요건이자 데이터 업로드 서비스의 법적 요건이므로 **정확성이 특히 중요함.** 실제 구현과 불일치하는 문구를 쓰지 않음(예: "즉시 삭제"라고 쓰고 실제로는 보관).

## 6. SEO·기술 요건

콘텐츠가 크롤러에 보이지 않으면 전략 전체가 무효임.

| 항목 | 요건 |
|---|---|
| 렌더링 | **빌드 스크립트가 원자료 md → HTML을 생성**해 커밋. 런타임에 JSON을 fetch해 그리지 않음 — 그 구조는 HTML에 "불러오는 중"만 남아 색인 코퍼스를 만들지 못함(실측 사례: 8페이지 합계 716자) |
| **확장자 없는 URL** | 내부 링크·canonical·sitemap·네비게이션을 전부 확장자 없이 통일 (`/pages/guide/multicollinearity`). `.html`을 가리키면 호스트가 **307 리디렉션**하고 GSC가 "리디렉션 오류"로 색인을 거부함 — 형제 프로젝트가 현재 이 문제로 sitemap 전량이 무효인 상태임 |
| sitemap.xml | 콘텐츠 페이지만 포함. **결과 화면과 정책 페이지 4종 제외**(§4). `<changefreq>`에 표준에 없는 값을 쓰면 오류로 잔존해 재수집이 막힘 |
| robots.txt | `Allow: /` + sitemap 위치. **`noindex` 페이지를 `Disallow` 하지 않음**(§4 주석) |
| 메타 태그 | 페이지별 title·description. 템플릿 중복 금지 |
| 정규 URL | 해설 페이지는 주제 기반 경로 |
| 내부 링크 | §3 연결 규칙 구현. 고립된 페이지 없음 |
| 구조화 데이터 | 해설 페이지에 Article, 하위 페이지에 BreadcrumbList, 홈에 WebSite·Organization. FAQ 항목이 있으면 FAQPage(**화면 텍스트와 100% 일치**). 실제 계정이 없으면 `sameAs`는 생략 |

## 7. AdSense 신청 게이트

**아래 조건을 전량 충족한 뒤에만 신청함.** 미달 상태 신청은 거절 이력을 남기므로 불리함. 신청 시점은 날짜가 아니라 **GSC 상태**로 판단함("2주 기다렸으니 신청"은 안 됨 — sitemap이 3주간 재수집되지 않은 전례가 있음).

**콘텐츠**
- [ ] 콘텐츠 페이지 15편 이상 발행
- [ ] **독자용 콘텐츠 25,000자 이상** — 실측 기준선(5,385자 거절 → 23,958자 신청 가능 판단, 통과권 사례 26,119자)
- [ ] 편당 800자 미달 문서 0건

**색인 인프라** (콘텐츠보다 먼저 확인할 것 — 세 프로젝트에서 반복해 발목을 잡은 지점임)
- [ ] **sitemap URL 전수가 307 리디렉션 대상이 아님** (§6)
- [ ] GSC Sitemaps 리포트 "성공" + 검색된 URL 수가 의도한 값과 일치
- [ ] 신규 콘텐츠 페이지가 URL 검사에서 "URL이 Google에 등록되어 있음"
- [ ] **홈의 마지막 크롤이 최신 배포 이후** (재크롤 전까지 새 내부 링크가 보이지 않음)
- [ ] 정책 페이지 4종이 색인에서 빠짐 (실시간 테스트로 `noindex` 확인)

**구성**
- [ ] 도구 정상 동작, 미완성·빈 페이지 0
- [ ] 필수 페이지 4종 완비 (§5)
- [ ] 도구 페이지의 초기 HTML에 결과 UI가 없음 — 렌더 텍스트가 도구 설명·FAQ로만 구성되는지 실측 (§4)
- [ ] 광고 배치 정책 구현 완료 (§4)
- [ ] `ads.txt` — 커스텀 도메인 확보 후 (서브도메인에서는 루트 소유 불가)
- [ ] §10 안티패턴 체크리스트 전항 통과

> **GSC 사용 시 함정**: 페이지 색인 리포트 숫자는 최대 10일까지 밀리므로 판단 근거로 쓰지 않고 URL 검사와 `site:` 검색만 신뢰함. `site:`에 프로토콜을 붙이면 매칭이 깨짐. URL 색인 요청은 속성당 하루 약 10건에서 막히므로 날짜별로 쪼갬. "URL을 Google에 등록할 수 있음"은 크롤 가능하다는 뜻이며 색인된 것이 아님.

## 8. 작성 순서

| 순서 | 대상 | 근거 |
|---|---|---|
| 1 | K1, K2, K3 | information gain 최고. 국내 검색 수요 확보 |
| 2 | Q1·Q2·Q5, D1·D3, R2·R5, T1 | Phase 1 Finding 유형과 직결. 도구 구현과 동시 진행 |
| 3 | C1, C2, 국내 사례 1건 | 데모 확보. Phase 1.5 완료 조건 |
| 4 | 잔여 해설 11편 | Phase 2~3 |
| 5 | 잔여 사례 3건 | Phase 3 |

용어집(`/pages/glossary`)은 순서 5 항목이었으나 해설 15편 발행 시점에 앞당겨 발행함 — 결과 화면의 용어를 확인하려면 해설 한 편을 통째로 열어야 하는 문제가 먼저 드러났기 때문임. 용어집은 정의와 판정 수치만 담고 깊은 설명은 해설로 넘겨 안티패턴 #4(문장 중복)를 피함.

**Phase 1.5 완료 기준**: 순서 1~3 완료 = 해설 11편 + 사례 3편 = 14편. 게이트 조건(15편)에 1편 부족하므로 순서 4에서 1편 이상을 앞당김.

## 9. 기대치 및 리스크

| 항목 | 판단 |
|---|---|
| 수익 규모 | 도구 사이트의 AdSense RPM은 낮음. 수익은 콘텐츠 검색 유입량이 결정하므로 초기 기대치를 낮게 잡아야 함. 수익화를 프로젝트의 성공 기준으로 삼지 않음 |
| 콘텐츠 부담 | 28편은 상당한 분량임. §8 순서대로 분할하고, 축소 시 순서 4~5를 후순위로 미룸 |
| 품질 하한 | 편수를 채우려 300자 수준 문서를 양산하면 오히려 거절 요인임. 편당 800자 미달 문서는 발행하지 않음 |
| **분량 계산 규칙** | **소개·개발 후기·제작 과정 같은 메타 콘텐츠는 독자용 분량으로 계산하지 않음.** 실측 사례에서 이 항목이 9,411자였는데도 거절됨 — 사이트 자신에 대한 글은 독자에게 주는 가치가 아님 |
| 심사 소요 | 승인은 최소 몇 달, 여러 차수를 각오해야 함(실측: 1차 신청부터 5차 준비까지 약 2개월) |
| 심사 불승인 시 | 콘텐츠·필수 페이지·내부 링크는 AdSense와 무관하게 제품 자산으로 남음. 재신청 전 부족 항목만 보강함 |

## 10. 안티패턴 체크리스트

같은 인프라에서 4회 거절을 겪으며 확인된 실제 거절 원인임. 콘텐츠를 추가할 때마다 대조함.

| # | 금지 | 이 프로젝트에서의 위험 지점 |
|---|---|---|
| 1 | **외부 데이터 재포장 페이지 양산** | 공개 데이터셋 통계를 그대로 나열한 사례 리포트. 반드시 **해석과 판단을 본문의 주(主)로** 두고, 표는 근거로만 씀 |
| 2 | **프로그램 생성 페이지 대량 발행** | 사례 리포트를 스크립트로 찍어내면 scaled content farming으로 판정됨. 소수를 손으로 깊게 씀 |
| 3 | **thin content로 편수 채우기** | 해설 22편을 서둘러 채우려는 유혹. 800자 하한을 지킴 |
| 4 | **템플릿 문장 반복** | Finding 해석 문구를 해설 페이지에 그대로 복사하면 페이지 간 문장이 동일해짐. 해설은 툴팁보다 깊게 다시 씀 — 문구 작성 규칙은 [`rules.md §5`](./rules.md) |
| 5 | **약점을 색인 페이지에 공표** | "아직 사용자가 없음", "기능 준비 중" 같은 문구를 색인 페이지에 두지 않음 |
| 6 | **진단만 하고 조치 없이 재신청** | 거절 사유를 기록해두고 조치하지 않은 채 재신청한 전례가 있음. 재신청 전 §7 게이트를 문서로 대조함 |
| 7 | **콘텐츠를 JSON+JS로만 렌더** | 해설·사례를 런타임 fetch로 그리면 HTML이 빈 셸이 됨. 빌드 시점 HTML 생성으로 회피(§6) |
| 8 | **홈 본문을 `noindex` 링크로 채움** | 정책 페이지 4종이 `noindex`이므로 홈 본문을 그 링크들로 채우면 텍스트 밀도만 늘고 코퍼스는 늘지 않음 |

**유효한 생산 패턴 (대비)**: 자체 데이터에서 실측을 캐고 그 위에 해설을 씀. 수치가 의외이거나 통념을 반박할 때만 문서로 만들고, 결과가 밋밋하면 **발행하지 않고 버림**. 이 프로젝트에서는 사례 리포트 작성 중 발견한 국내 공공데이터의 실제 품질 문제가 그 소재가 됨.
