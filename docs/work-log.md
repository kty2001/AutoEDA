## 2026-08-19 — 결과 화면 표시 결함 3건: 버튼 겹침 · 막대 레이블 잘림 · 히트맵 수치

실사용 화면에서 확인된 결함만 고침. 기능·임계값은 건드리지 않았고 전부 치수·레이아웃 문제였음.

### 결정 — 공용 캔버스 예외를 막대에도 준다

- 막대는 공용 규격(400×220, 좌 48·우 12 여백)을 쓰는데, 범주 레이블은 `x = 42` 에
  `text-anchor="end"` 로 그려지면서 12자(한글 ≈ 120단위)까지 허용됐고, 최대 막대의 수치는
  `48 + 340 + 4 = 392` 에서 시작해 폭 400 밖으로 나갔음. **양쪽 다 viewBox 잘림**이었음
- 히트맵이 이미 쓰던 종류별 캔버스 예외(`CANVAS`)를 막대에도 적용해 `480×260` + `BAR` 여백
  (좌 128 · 우 56)으로 자리를 확보함. 절단 길이는 `BAR_LABEL_MAX = 10` 으로 낮추고
  절단된 전체 값은 막대 `<title>` 로 남김 — 히트맵 셀과 같은 관례
- `renderAxis` 가 공용 `PLOT`·`H` 에 하드코딩돼 있어 새 캔버스에서 축이 어긋났음.
  **선택 인자 `plot`·`height`** 를 받게 하고 기본값을 공용 규격으로 둠 — 기존 호출부 4곳 무변경

### 결정 — 히트맵 셀에 수치를 직접 쓴다

- 수치가 `<title>` 툴팁에만 있어 화면에서 읽을 수 없었음. 셀을 키워야 글자가 들어가므로
  캔버스를 420 → **640**, `HEAT` 여백을 88 → **112** 로 올림(20열 기준 셀 16 → 25.6단위)
- 셀 폭에 4자를 넣기 위해 **선행 0 을 뗀 표기**를 씀(`0.83 → .83`, 대각선 → `1`).
  폰트는 `min(12, 셀 × 0.36)` 이며 7 미만이면 그리지 않음 — 그때도 수치는 `<title>` 에 남음
- 짙은 극색 위에서 검은 글자가 읽히지 않으므로 흰 글자로 뒤집되, **`|r|` 로 자르지 않음** —
  녹색 극(#00754a)과 적색 극(#c82014)의 휘도 곡선이 달라 뒤집히는 지점이 각각 |r| ≈ 0.86 · 0.80
  으로 갈림. 채움의 상대 휘도 0.179(흰색 대비와 검정 대비가 교차하는 값, 그 지점 4.58:1)로 판정함
- 인라인 `style` 금지(CSP)라 **클래스**(`.cell-value-on-dark`)로 가름. 셀 수치에만 순수 검정을 씀 —
  본문의 `--fg`(알파 0.87)로는 교차 지점 대비가 4.37:1 로 AA 에 못 미침

### 결정 — 변수별 탭 2열 + 도구 화면만 넓은 본문

- 차트가 `max-width: 480px` 1열 스택이라 900px 본문의 절반이 비어 있었음.
  `.column-grid` 2열(900px 이하 1열)로 깔고 `main` 에 `.container-wide`(1200px)를 줌
- `--maxw` 토큰을 요소에서 덮는 방식이라 `.container` 규칙 자체는 그대로 둠
- 넓힌 폭이 결과 아래 한글 산문까지 늘리면 읽기 어려워지므로 그 구역만 `.prose`(900px)로 되돌림

### 함정 (되풀이하지 말 것)

- **`renderFindings` 의 "전체 보기" 버튼이 `<p>` 없이 패널에 직접 붙어 있었음** — 알약 버튼은
  `display: inline-block` 에 여백이 없어 바로 아래 결과 액션 버튼 줄(`analyze.html`)과 맞닿아
  한 덩어리로 보였음. `<p>` 로 감싸고, 닫을 때 버튼이 아니라 **`<p>` 를 지움**(빈 문단 여백 잔류 방지)
- **절단 기호 `…` 도 한글 한 자 폭을 먹음** — 10자 절단이면 실제 폭은 11자 기준으로 잡아야 함.
  `BAR.left` 를 112 로 뒀다가 회귀 테스트에서 6단위 초과로 걸려 128 로 올림
- `tests/chart.test.js` 의 "폰트 ≤ 셀 크기" 회귀는 `class="tick"` 만 훑음. 셀 수치는 다른
  클래스라 같은 불변식을 검사하는 테스트를 따로 추가했음

### 검증

`npm test` 266건 통과 (기존 262 + 신규 4: 막대 잘림 2 · 히트맵 셀 수치 2).

## 2026-08-19 — DESIGN.md 구조 3종 반영: 히어로 40/60 · feature band · 플로팅 CTA

`DESIGN.md` 최상단이 스스로 남긴 유일한 미반영 항목이었음. 2026-08-18 개편이 토큰·컴포넌트까지만
간 이유는 구조가 **손으로 쓴 HTML + `build_guides` 템플릿을 함께 고쳐야 해서**였고, 이번에 함께 처리했음.

### 결정 — 히어로 40% 칸을 결과 미리보기 카드로 채움

- 원문 규격은 제품 사진 40% / 텍스트 60% 인데 사진 자산이 없음. `DESIGN.md` §4 는
  "generic generated graphics" 를 금지하므로 **장식 일러스트를 새로 만들지 않음**
- 대신 도구가 실제로 그리는 마크업(`js/app/analyze.page.js` 의 `.health-total`·`.finding`·`.badge`)을
  **그대로 정적 HTML 로** 둠. 새 CSS 없이 기존 컴포넌트가 그대로 걸리고,
  `.health-total:has(.verdict-ok)` 의 금색 테두리 규칙도 자동으로 붙음
- 수치는 배포본 검증 때 실측한 값(Health 88)을 쓰고 `<figcaption>` 으로 예시임을 밝힘 —
  실제 분석 결과로 오인되면 그 자체가 허위 신호임

### 결정 — 전면 폭은 `50vw` 되밀기 + `overflow-x: clip` 으로 받음

- 전 페이지가 `<main class="container">`(max-width 900px) 라 밴드가 컨테이너 안에 갇힘.
  구조를 바꾸면 손으로 쓴 HTML 7개 + 템플릿을 전부 고쳐야 하므로,
  `margin-inline: calc(50% - 50vw)` + `padding-inline: calc(50vw - 50%)` 로 되밀었음.
  두 값의 백분율 기준은 **컨테이너 본문 폭**이라 정확히 상쇄됨 — 여기에 `--sp-4` 를 더하면
  밴드 본문만 16px 안으로 들어가 나머지 본문과 좌측 정렬이 어긋남(계산으로 확인)
- `50vw` 는 스크롤바 폭을 포함해 그만큼 가로 넘침이 생김. `body { overflow-x: clip }` 으로 받음 —
  **`hidden` 이 아니라 `clip`** 인 이유는 `clip` 이 스크롤 컨테이너를 만들지 않아
  고정 요소(전역 메뉴 버튼·패널)에 영향이 없기 때문임

### 결정 — 본문 하단 `.cta` 는 전면 폭으로 올리지 않음

전면 폭으로 바꾸면 짙은 녹색 푸터와 맞붙어 하나의 큰 다크 블록이 되고,
`DESIGN.md` §1 의 색블록 교대 리듬(크림↔다크)이 오히려 무너짐. 24개 페이지 하단을
한꺼번에 회귀 대상으로 만들 이유도 없음. `.band` 를 신설하고 버튼 반전 규칙만 공유함.

### 결정 — 플로팅 CTA 의 제외 판정을 모듈 안에 둠

- `js/app/float-cta.js` 는 `js/app/menu.js` 와 같은 패턴 — import 만으로 스스로 body 에 붙고,
  각 HTML 에는 스크립트 한 줄만 둠
- 도구 화면 제외를 "그 페이지에는 스크립트 줄을 넣지 않는다" 로 처리하지 않았음.
  **빠뜨림으로 지키는 규칙은 언젠가 깨짐.** `shouldMount(pathname)` 순수 함수를 두고
  `common.normalizePath()` 를 재사용해 `.html`·꼬리 슬래시로 들어와도 같은 판정이 나오게 했음

### 함정

- **`npm run build | head` 는 `build:seo` 를 건너뜀.** 파이프가 닫히면 `&&` 체인이 거기서 죽어

## 2026-08-18 — T6 재검토 2건: 히트맵 축 레이블 · `F-MIXED-RELATION` 폐지

`TODO.md` T6 의 재검토 항목 중 실기·설계 문서가 이미 결함으로 특정한 2건을 처리했음.

### 결정 — 히트맵에 종류별 캔버스를 도입함

- **레이블을 추가하는 것만으로는 풀리지 않았음.** 공용 캔버스(`400 × 220`)에서 셀 크기는
  `min(PLOT.w, PLOT.h) / n` 이라 20열이면 8.6단위인데 `text()` 는 `font-size="10"` 고정이었음.
  즉 **열 레이블이 없던 것이 아니라 넣을 자리가 없었고, 있던 행 레이블조차 겹치는 상태**였음
- `renderChart` 에 종류별 캔버스 조회표(`CANVAS`)를 두고 히트맵만 정사각 `420 × 420` 을 쓰게 했음.
  렌더러 계약 `(data, axis) => string` 은 그대로라 나머지 4종은 한 줄도 바뀌지 않음
- 열 레이블은 매트릭스 아래에 **−45° 회전**. `transform` 은 presentation attribute 이므로
  CSP `style-src 'self'`(인라인 style 금지) 규약을 어기지 않음. 회전 레이블 간 유효 간격은
  `셀 × sin45 ≈ 11단위` 로 폰트보다 큼
- **폰트 크기를 셀 크기에 종속**시켰음(`max(6, min(10, 셀 × 0.85))`). 겹침을 눈이 아니라 치수로 막고,
  테스트가 `폰트 ≤ 셀` 을 단정해 회귀를 잡음
- **`DISPLAY_LIMIT.heatmapColumns = 20` 은 건드리지 않았음** — 위 치수면 20열에서 셀이 15.8단위라
  판독됨. 표시 상한은 `rules.md §4` 확정본이므로 화면 사정으로 흔들지 않는 편이 나음

### 함정 (되풀이하지 말 것)

- **`truncate` 가 이스케이프한 뒤에 잘랐음** — `&amp;` 같은 엔티티가 반토막 나면 SVG 가
  파싱 오류로 **통째로** 사라짐(차트 하나가 아니라 그 svg 전체). 원문 길이로 자른 뒤 이스케이프하도록
  순서를 뒤집었음. 한글 열 이름은 8자에서 잘리므로 이 경로를 실제로 밟았을 것임
- **`text()` 의 font-size 를 하드코딩해 두면 캔버스를 바꿔도 레이블이 따라오지 않음.** 기본값 인자로
  풀어 두면 기존 호출부는 무변경으로 남음

### 결정 — `F-MIXED-RELATION` 을 발견에서 폐지하고 관계 탭 안내로 옮김

- `rules.md §6.3` 이 **"구현 시 첫 재검토 대상"** 으로 예고한 그대로였음. 조건이
  `범주형 ≥ 1 이고 수치형 ≥ 1` 이라 실데이터에서 사실상 항상 발화했고, **항상 나오는 발견은 정보량이 0** 임
- 문구 자체는 틀리지 않았으므로 지우지 않고 **관계 탭 상단 고정 안내**로 옮겼음
  (`analyze.page.js` `renderMixedRelationNote`). 상관행렬 옆에서만 뜻이 있는 문장이고,
  거기서는 상시 노출이 잡음이 아니라 맥락임

## 2026-08-17 — `build_seo.mjs` 구현 (T2-1)

canonical·OG·JSON-LD 주입과 `sitemap.xml` 생성. 콘텐츠가 한 편도 없는 상태에서도 배포(T3)를 막지 않게 하는 것이 목적임.

### 결정

- **미생성 빌드 산출물은 오류가 아니라 경고 후 제외** — `PAGES` 의 `/pages/guide`·`/pages/case` 인덱스는 `build_guides`·`build_cases` 산출물이라 콘텐츠 착수 전에는 없음. `generated: true` 로 표시하고, 없으면 목록에서 뺌. **없는 URL 을 sitemap 에 넣는 것이 정확히 "sitemap 전량 무효"를 만드는 경로**이므로 넣지 않는 쪽이 맞음. 수기 페이지가 없으면 그건 목록과 저장소가 어긋난 것이므로 exit 1
- **하위 페이지 목록은 파일 시스템에서 스캔** — 해설·사례 슬러그를 `PAGES` 에 수기로 적으면 발행과 sitemap 이 어긋남. 산출물 디렉토리가 원천임
- **정책 4종에는 canonical·OG 를 주입하지 않음** — `noindex` 페이지에 색인 신호를 붙일 이유가 없음. 자리 표시 주석이 색인 대상 2개 페이지에만 있는 것이 원저자 의도로 보이고 그에 맞춤. **검사(noindex 유무)는 4종도 그대로 받음**
- **주입은 `<!-- build:seo:begin/end -->` 경계로 감싸고 자리 표시 주석은 앵커로 남김** — 재실행 시 경계 사이를 걷어내고 다시 넣으므로 멱등함. 마커를 소비해 버리면 두 번째 실행이 "마커 없음"으로 실패함
- **`FAQPage` 는 페이지 HTML 자신에서 추출** — 별도 원고로 만들면 화면 텍스트와 어긋나 구조화 데이터 위반이 됨(`content-strategy.md §6` "100% 일치"). `<h2>자주 묻는 질문</h2>` 다음 `<h2>` 직전까지의 `h3`/`p` 쌍만 뽑음
- **`sameAs` 생략** — 실제 계정이 없는 상태에서 넣으면 허위 신호임
- **`<changefreq>`·`<priority>` 미출력** — 구글이 무시하고, 표준에 없는 값이 들어가면 오류로 잔존해 재수집이 막힘
- **검사 → 조립 → 쓰기 3단** — 한 페이지라도 실패하면 아무 파일도 쓰지 않음(규약 7). 절반만 주입된 상태는 눈으로 알아채기 어려움

### 함정 (되풀이하지 말 것)

- **JSON-LD 의 `<` 를 `<` 로 이스케이프하지 않으면 `</script>` 가 든 description 하나로 블록이 조기 종료됨** — `JSON.stringify` 는 이것을 막아주지 않음. 테스트로 고정함
- **CSP `script-src 'self'` 는 `application/ld+json` 을 막지 않음** — 실행 스크립트가 아니라 데이터 블록임. 실기로 확인함(파싱 성공, 콘솔 오류 없음)
- **`description` 이 JSON-LD 본문에 들어가는 페이지는 일부뿐** — `WebSite`·`Article` 만 담고 `BreadcrumbList` 는 담지 않음. 이스케이프 테스트를 아무 페이지로나 짜면 통과하지 않음

### 검증

## 2026-08-17 — 브라우저 실기 검증 (T1)

Phase 1 런타임을 실제 브라우저에서 처음 돌림. **검증 항목 11건 중 10건 통과, 결함 1건 발견·수정.**

### 검증 환경을 `wrangler dev` 로 바꿈

`npm run serve`(`python -m http.server`)로는 T1 의 핵심 항목을 검증할 수 없음 — `_headers` 의 CSP 를 보내지 않고 확장자 없는 URL 이 404 임. 즉 "CSP 위반 없음"과 "내부 링크 정상"을 **둘 다 확인할 수 없는 서버**임. `npx wrangler dev` 는 `_headers`·`_redirects`·`html_handling` 을 실제 배포와 같게 적용하므로 이쪽으로 검증함.

CSP 가 실제로 걸려 있는지는 양성 대조로 확인함 — 페이지에서 `style` 속성을 단 요소를 만들어 색이 적용되지 않는 것을 보고서야 "위반 로그 없음"이 의미를 가짐. 대조 없이 콘솔이 조용한 것은 CSP 가 없는 것과 구분되지 않음.

### 결함 1건 — 전역 메뉴가 항상 열려 있었음

`menu.js` 는 `panel.hidden` 만으로 여닫는데 `css/style.css` 의 `.menu-panel { display: flex }` 가 `hidden` 의 UA 스타일(`display:none`)을 이김. 결과적으로 **모든 페이지에서 메뉴 패널이 처음부터 펼쳐진 채로 있었고 ☰ 버튼은 `aria-expanded` 만 바꾸는 무동작 버튼이었음.** `.menu-panel[hidden] { display: none; }` 추가로 해소.

Node 테스트가 잡을 수 없는 유형임 — JS 는 정확히 명세대로 동작했고 어긋난 것은 CSS 와의 상호작용임. 같은 파일의 `#resume-notice`·탭 패널·발견 목록은 `display` 를 지정하지 않아 우연히 무사했음.

### 함정 (되풀이하지 말 것)

- **`hidden` 으로 여닫는 요소에 `display` 를 지정하면 안 열리는 게 아니라 안 닫힌다** — 실패가 "보이지 않음"이 아니라 "항상 보임"으로 나타나므로 기능이 죽은 티가 나지 않음. `hidden` 을 쓰는 컴포넌트에 CSS 로 `display` 를 줄 때는 `[hidden]` 규칙을 짝으로 넣을 것
- **`wrangler dev` 의 자산 디렉토리가 프로젝트 루트(`"./"`)면 무한 리로드 루프에 빠짐** — wrangler 가 `.wrangler/` 상태를 감시 대상 안에 쓰고 그것이 다시 리로드를 부름. `--persist-to` 로 상태 디렉토리를 프로젝트 밖에 두면 멈춤. 배포(`deploy`)에는 영향 없음
- **브라우저 확장이 DOM 에 인라인 style 요소를 주입함** — 인라인 style 누수를 셀 때 `document.querySelectorAll('[style]')` 전수로 세면 확장 요소가 잡혀 오탐임. `main`·`header`·`footer` 안으로 한정해 셀 것 (앱 코드 기준 0건)

### 재검토로 넘긴 것 (수정하지 않음)

- **상관 히트맵에 열(x축) 이름이 없음** — `chart-svg.js` heatmap 이 행 이름만 그림(227행). 셀마다 `<title>` 툴팁은 있으나 최대 20열까지 늘어나는 히트맵을 눈으로 읽을 수 없음. 명세가 열 이름을 요구한 적이 없어 T1 범위 밖으로 두고 [`TODO.md` T6](TODO.md)에 올림 — 20열 라벨은 회전·절단 설계가 필요해 한 줄 수정이 아님

## 2026-08-16 — storage 구현 (local) + worker 가드 교정

### 결정

- **축소 단계는 입력을 변형하지 않음** — `saveResult` 의 1·2단계는 얕은 복제로 새 객체를 만듦. 화면이 들고 있는 결과에서 histogram 이 사라지면 캐시 폴백이 화면 버그로 둔갑함
- **2단계 상관 축소 기준 = 규칙 임계값 재사용** — |Pearson| ≥ `F-CORR-CAUSAL`(0.7, 가장 낮은 상관 임계) 또는 VIF ≥ `F-MULTICOLLINEAR`(10). 자의적 수치를 새로 만들지 않고 Finding 근거 쌍이 보존되는 최소선을 택함
- **3단계 포기 시 이전 캐시도 삭제** — 남겨 두면 해설에서 복귀했을 때 다른 파일의 옛 결과가 보임
- **깨진 캐시·major 불일치는 읽는 시점에 삭제** — 복귀할 때마다 같은 실패를 반복하지 않음. minor 차이는 허용([`data-model.md §4`](data-model.md) 버전 정책)
- **스키마 major 를 `RESULT_SCHEMA_MAJOR` 로 별도 보유** — worker 모듈을 import 하면 엔진 전체가 페이지 번들에 끌려옴. 대신 worker 산출물의 major 와 일치하는지를 테스트가 대조해 드리프트를 막음
- **prefs 는 병합 저장(patch)** — 화면 조각들이 각자 자기 키만 갱신해도 서로를 지우지 않음

### 함정 (되풀이하지 말 것)

- **worker 글루 가드로 `typeof self` 를 쓰지 말 것** — 일반 페이지의 `window.self` 도 참이라 window 의 `message` 이벤트(타 출처 postMessage 포함)에 파이프라인이 배선됨. `self instanceof WorkerGlobalScope` 로 판정해야 함
- **Node 테스트에서 Web Storage 는 전역 주입으로 흉내냄** — `globalThis.sessionStorage = new FakeStorage()`. 모듈이 전역을 호출 시점에 참조하므로 import 순서 제약이 없음

### 검증

## 2026-08-16 — 판정 축 구현 (quality · finding)

### 결정

- **penalty 는 항목별 반올림 후 합산** — `items[].penalty` 가 int([`data-model.md §3.4`](data-model.md))이므로 반올림 지점을 항목 단위로 고정. 합산 후 반올림하면 항목 합계와 총점이 어긋나 보임
- **verdict 의 ok 경계**: `비율 === 0 이거나 < ok` 면 ok — duplicate·invalid 의 ok 경계가 0 이라 "0 → ok" 문면([`rules.md §2.1`](rules.md))과 `< 경계` 규칙을 하나의 식으로 합침
- **cardinality 판정에 `F-HIGH-CARD` 임계값을 재사용** — §2.1 에 별도 수치가 없고 대상이 같은 "고카디널리티 범주형"이므로 기준을 이원화하지 않음
- **evidence 의 열 목록은 최악 5개로 절단** — 근거 노출이 목적이지 전체 나열이 목적이 아님
- **묶음 항목(`collapseByType`)의 형태**: 대표 5건 유지 + `{type}#more` id·`collapsed: true`·targets 에 묶인 열 전부를 담은 합성 항목 1건을 대표 바로 뒤에 삽입. 별도 필드에 숨기면 표현 레이어가 목록 렌더링 외의 특수 경로를 갖게 됨
- **기본 표시 15건 상한은 여기서 자르지 않음** — 자르면 "전체 보기" 펼침(UC-05)이 불가능함. 정렬을 여기서 확정하고 화면이 앞 15건만 보여주는 분담

- **문구는 lib/format 의 percent·stat·count 로 주입** — 화면 표기와 Finding 문구의 수치 표기가 갈리면 안 됨(format.js 존재 이유)

## 2026-08-16 — 통계 축 구현 (stats · outlier · correlation)

### 결정

- **추정량 선택을 `stats.js` 헤더에 고정** — 표본 std(n-1, pandas 기본과 동일), 분위수는 R-7 선형 보간(numpy 기본), 왜도·첨도는 모집단 적률 기반 g1·g2(초과첨도). 테스트 기준값이 이 선택에 결부되므로 바꾸면 테스트도 함께 바꿔야 함
- **상수 열의 왜도·첨도는 0 반환** — 수학적으로 정의 불가(m2=0)지만 NaN 은 JSON 직렬화에서 깨지고, 0 은 "편포 신호 없음"으로 Finding 판정(≥ 비교)과 정합
- **상관의 결측 처리**: pearson·spearman 은 쌍별 제거(pairwise), VIF 는 전행 완전 케이스(listwise). 열 배열은 행 정렬을 유지한 전체 길이(결측=NaN)로 받음 — `stats`·`outlier`가 결측 제외 배열을 받는 것과 다르므로 worker 조립 시 주의
- **완전 공선(R²≈1)·특이 행렬의 VIF 는 null** — 무한대는 JSON 으로 나갈 수 없고, 그 경우 Pearson |1| 이 이미 `F-MULTICOLLINEAR`(OR 조건)를 성립시키므로 정보 손실 없음
- **히스토그램 기본 빈 수는 Sturges 규칙**(⌈log2 n⌉+1, 최대 50). 등폭 구간, 최댓값은 마지막 구간에 포함
- **`topValues` 동률은 등장 순서 유지** — 정렬 불안정으로 실행마다 결과가 흔들리면 재현성이 깨짐

### 함정 (되풀이하지 말 것)

- **`const F = Float64Array.from` 처럼 정적 메서드를 변수로 떼어내면 `this` 바인딩이 끊겨 TypeError** — 테스트 헬퍼에서 전 케이스가 일괄 실패했음. 화살표 함수로 감쌀 것

### 검증

`npm test` 98건 통과 (계약 21 + 동작 77).

## 2026-08-16 — 입력 축 구현 (decode · parse · infer) + format

### 결정

- **파일 크기 상한 25MB 확정** — 근거와 상수 위치는 [`direction.md §9`](direction.md) 결정된 사항 참조
- **결측 = trim 후 빈 문자열만.** `NA`·`미상` 같은 표기는 값이 있는 것이므로 `invalidCount`로 셈 — [`data-model.md §3.3`](data-model.md)의 결측/불일치 구분과 정합. 결측 토큰 목록(`NA`, `null` 등) 도입은 실데이터에서 필요가 확인되면 검토
- **`PARSE_FAILED` 임계 = 1건.** 필드 수가 어긋난 행이 하나라도 있으면 즉시 실패 — 어긋난 행을 조용히 버리거나 메우면 통계가 왜곡되고 사용자가 알아챌 수 없음. 완화(비율 허용)는 실데이터 불만이 쌓이면 검토
- **0/1 은 boolean 으로 잡지 않음** — 수치 이진 변수와 구분 불가. boolean 토큰은 true/false·yes/no·y/n·t/f
- **`modeRate` 분모 = 비결측 수** — 결측이 많은 열에서도 관측값의 상수성을 판정해야 `F-CONST-COL`이 성립
- **전결측 열은 `text` 타입** — 타입을 단정할 근거가 없고 통계를 산출하지 않는 타입이 안전함
- **빈 헤더는 `col_N`, 동명 헤더는 `name_2` 부여** — 이름 참조 유일성([`data-model.md §3.3`](data-model.md))
