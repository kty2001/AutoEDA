## 2. Health Score 감점 규칙

100점에서 시작해 항목별로 감점함. 항목 6종이며 **각 항목의 감점 상한이 정해져 있어 한 항목이 총점을 지배하지 못함.**

| 항목 키 | 대상 | 판정 기준 | 감점 상한 |
|---|---|---|---|
| `missing` | 결측 | 열별 결측률의 가중 평균 | 25 |
| `duplicate` | 중복 행 | 중복 행 비율 | 15 |
| `constant` | 상수·준상수 열 | 해당 열 수 / 전체 열 수 | 15 |
| `cardinality` | 고카디널리티 범주형 | 해당 열 수 / 범주형 열 수 | 15 |
| `outlier` | 이상치 | 수치형 열의 이상치율 평균 | 15 |
| `invalid` | 유효하지 않은 값 | 타입 불일치 값 비율 | 15 |

합계 상한 100. 총점이 0 미만이 되지 않게 하한을 둠.

### 2.1 항목별 계산식

| 항목 | `verdict` 기준 | 감점 계산 |
|---|---|---|
| `missing` | 평균 결측률 `< 5%` → `ok` / `< 20%` → `warn` / 이상 → `bad` | `min(25, 평균결측률 × 100)` |
| `duplicate` | `0` → `ok` / `< 5%` → `warn` / 이상 → `bad` | `min(15, 중복비율 × 300)` |
| `constant` | `modeRate ≥ 0.95`인 열 수. `0개` → `ok` / `1개 이상` → `warn` / `전체의 20% 이상` → `bad` | `min(15, 해당열수 × 5)` |
| `cardinality` | `0개` → `ok` / `1개 이상` → `warn` / `범주형의 50% 이상` → `bad` | `min(15, 해당열수 × 5)` |
| `outlier` | 평균 이상치율 `< 1%` → `ok` / `< 5%` → `warn` / 이상 → `bad` | `min(15, 평균이상치율 × 300)` |
| `invalid` | `0` → `ok` / `< 1%` → `warn` / 이상 → `bad` | `min(15, 불일치비율 × 500)` |

`evidence`에는 계산에 쓴 원값(평균 결측률, 해당 열 이름 목록 등)을 담아 화면에 노출함.

### 2.2 등급 구간

| 총점 | `grade` | 화면 표기 |
|---|---|---|
| 80~100 | `good` | 양호 |
| 50~79 | `fair` | 주의 |
| 0~49 | `poor` | 문제 있음 |

**등급을 3단으로만 두는 이유**: 구간을 세분하면 점수 1~2점 차이가 의미 있는 것처럼 보임. 감점 계산이 근사치인 만큼 해상도를 낮게 유지함.

### 2.3 산정 대상에서 제외하는 열

`id`·`text` 타입 열은 `missing`을 제외한 모든 항목에서 제외함. ID 열의 고유값이 100%인 것은 정상이므로 `cardinality`로 감점하면 오판임(대신 `F-ID-COL` Finding으로 알림).

## 3. Finding 규칙 카탈로그

18종. `content-strategy.md §2`의 "대응 Finding" 열에서 도출됨. `F-MIXED-RELATION`은 발행 후 폐지했음(§6.3).

### 3.1 Finding ↔ 해설의 비대칭

**Finding 18종 ↔ 해설 19편(Q·D·R·T군)은 1:1에 가깝지만, 역방향은 성립하지 않음.** K군 3편은 프로세스 문서라 Finding에서 도달하지 않고, R4(`categorical-numeric-relation`)는 대응 Finding을 폐지해 **관계 탭 고정 안내**에서 도달함(§6.3).

| 해설군 | 편수 | Finding 대응 |
|---|---|---|
| Q 데이터 품질 | 6 | ○ (F-MISSING-HIGH ~ F-ID-COL) |
| D 분포 | 5 | ○ (F-SKEW ~ F-BIN-SENSITIVE) |
| R 관계 | 5 | △ (F-CORR-METHOD ~ F-LEAKAGE. R4 는 관계 탭 안내에서 도달) |
| T 타깃·모델링 | 3 | ○ (Phase 2의 UC-21에서 활성) |
| **K 프로세스·한국 환경** | **3** | **× — `finding-map.json`에 등장하지 않음** |

K1(EDA 진행 순서)은 `/pages/guide` 인덱스 본문이고, K2(인코딩)는 오류 상태 D에서 안내로 연결되며, K3(공공데이터 함정)은 사례 리포트에서 링크됨. 즉 **도달 경로가 Finding이 아닌 다른 곳에 있음.** UC-15의 "모든 Finding 유형이 대응 해설을 가짐"은 성립하고, 그 역은 요구되지 않음.

### 3.2 데이터 품질군 (6종)

| ID | 발생 조건 | 심각도 | 범위 | 해설 슬러그 | ML |
|---|---|---|---|---|:---:|
| `F-MISSING-HIGH` | 열 결측률 ≥ 20% | high | column | `missing-types` | × |
| `F-MISSING-IMPUTE` | 열 결측률 5~20% **이고** 해당 열 왜도 절댓값 ≥ 1 | medium | column | `missing-imputation` | ○ |
| `F-DUP-ROW` | 중복 행 ≥ 1 | medium | dataset | `duplicate-rows` | × |
| `F-CONST-COL` | `modeRate ≥ 0.95` — **타입 무관 적용** | high | column | `constant-columns` | ○ |
| `F-HIGH-CARD` | 범주형 열의 고유값 ≥ 50 **이고** 고유값 비율 ≥ 50% | medium | column | `high-cardinality` | ○ |
| `F-ID-COL` | 고유값 비율 ≥ 99% **이고** 타입이 `id`로 추론됨 | low | column | `id-columns` | ○ |

`F-MISSING-IMPUTE`가 왜도 조건을 함께 보는 이유: 평균 대치의 위험은 분포가 치우쳐 있을 때 커지므로, 결측률만으로 대치 권고를 내면 근거가 약함.

`F-CONST-COL`이 `modeRate`를 쓰는 이유: **수치형 준상수**(상태코드 열의 99%가 동일한 값인 경우 등)를 잡아야 함. `std == 0`은 완전 상수만 걸러내고, `stats.topValues`는 범주형·불리언에만 채워지므로 타입을 가리지 않는 공통 필드가 필요함 ([`data-model.md §3.3`](./data-model.md)).

### 3.3 분포군 (5종)

| ID | 발생 조건 | 심각도 | 범위 | 해설 슬러그 | ML |
|---|---|---|---|---|:---:|
| `F-SKEW` | 왜도 절댓값 ≥ 2 | medium | column | `skewness` | ○ |
| `F-KURTOSIS` | 초과첨도 ≥ 7 | low | column | `kurtosis` | × |
| `F-OUTLIER-RATE` | IQR 기준 이상치율 ≥ 5% | medium | column | `outlier-methods` | × |
| `F-OUTLIER-ACTION` | 이상치율 ≥ 1% **이고** 왜도 절댓값 ≥ 1 | low | column | `outlier-removal` | ○ |
| `F-BIN-SENSITIVE` | 고유값 ≤ 20 **이고** 타입이 `numeric` | low | column | `histogram-bins` | × |

`F-BIN-SENSITIVE`는 이산적 수치(평점 1~5, 층수 등)를 연속형처럼 히스토그램으로 그리면 오해를 부르는 경우를 알림. 문제가 아니라 **해석 주의 안내**이므로 심각도 low임.

### 3.4 관계군 (4종)

| ID | 발생 조건 | 심각도 | 범위 | 해설 슬러그 | ML |
|---|---|---|---|---|:---:|
| `F-CORR-METHOD` | 수치형 열 중 왜도 절댓값 ≥ 2인 열이 1개 이상 존재 | low | dataset | `correlation-coefficients` | × |
| `F-MULTICOLLINEAR` | Pearson 절댓값 ≥ 0.8 **또는** VIF ≥ 10 | high | pair | `multicollinearity` | ○ |
| `F-CORR-CAUSAL` | Pearson 절댓값 ≥ 0.7인 쌍이 1개 이상 존재 | low | dataset | `correlation-causation` | × |
| `F-LEAKAGE` | 타깃 지정 시 특정 열과 타깃의 Pearson 절댓값 ≥ 0.95 | high | pair | `data-leakage` | ○ |

`F-CORR-METHOD`는 편포 열이 있을 때 Pearson보다 Spearman이 적절할 수 있음을 알리는 안내형 Finding임. `F-CORR-CAUSAL`도 같은 성격으로, 상관이 높을 때 인과 해석을 경계하게 함.

VIF 10과 상관 0.8은 관례적 기준임(§6).

### 3.5 타깃·모델링군 (3종) — Phase 2

타깃 변수 지정(UC-21) 시에만 활성화됨. Phase 1에서는 생성되지 않음.

| ID | 발생 조건 | 심각도 | 범위 | 해설 슬러그 | ML |
|---|---|---|---|---|:---:|
| `F-CLASS-IMBALANCE` | `classDistribution`의 최소 클래스 비율 ≤ 10% | high | column | `class-imbalance` | ○ |
| `F-TARGET-SKEW` | 회귀 타깃의 왜도 절댓값 ≥ 1 | medium | column | `target-distribution` | ○ |
| `F-SCALE-DIFF` | 수치형 열 간 표준편차 최대/최소 비 ≥ 100 | medium | dataset | `scaling` | ○ |

### 3.6 필요 지표 폐합

§2(Health Score)와 §3(Finding)의 모든 조건이 참조하는 지표는 전부 [`data-model.md §3`](./data-model.md)에 필드로 존재해야 함. 대조표:

| 참조 지표 | 스키마 경로 | 쓰는 곳 |
|---|---|---|
| 결측률 | `columns[].missingRate` | §2 `missing`, F-MISSING-* |
| **타입 불일치 비율** | `columns[].invalidRate` | §2 `invalid` |
| 왜도 / 초과첨도 | `columns[].stats.skewness` / `.kurtosis` | §3 F-SKEW, F-KURTOSIS 외 |
| 이상치율 | `columns[].stats.outlierRate` | §2 `outlier`, F-OUTLIER-* |
| 고유값 수 / 비율 | `columns[].uniqueCount` (÷ `dataset.rowCount`) | §2 `cardinality`, F-HIGH-CARD, F-ID-COL |
| **최빈값 비율** | `columns[].modeRate` | §2 `constant`, F-CONST-COL |
| **최소 클래스 비율** | `columns[].classDistribution` | F-CLASS-IMBALANCE |
| 중복 행 | `dataset.duplicateRowCount` | §2 `duplicate`, F-DUP-ROW |
| Pearson / VIF | `correlations[].pearson` / `.vif` | F-MULTICOLLINEAR, F-CORR-CAUSAL, F-LEAKAGE |
| 표준편차 | `columns[].stats.std` | F-SCALE-DIFF |
| 타입 | `columns[].type` | 전반 |

**계산 불가능한 규칙이 없음을 이 표로 보장함.** 새 규칙을 추가할 때 지표가 스키마에 없으면 스키마를 먼저 늘려야 함.

### 폐합 검사 이력

이 대조는 세 차례 수행에서 매번 결함을 잡아냈음. **규칙을 추가·수정할 때 생략하지 않는 필수 절차임.**

| 회차 | 발견한 결함 | 해소 |
|---|---|---|
| 1차 | `invalidRate`가 스키마에 없어 §2의 `invalid` 항목이 계산 불가 | `columns[].invalidRate` 추가 |
| 2차 | `numeric` 타입에 `topValues`가 없어 **수치형 준상수**를 판정할 수 없음 (`F-CONST-COL`·§2 `constant`) | `columns[].modeRate`를 타입 무관 공통 필드로 추가 |
| 2차 | `F-CLASS-IMBALANCE`가 **최소** 클래스 비율을 요구하는데 `topValues[0]`(최빈값 = **최대**)를 가리켜 논리가 성립하지 않음. `topValues`가 상위 N개만 담아 최소 클래스가 잘리는 문제도 겹침 | `columns[].classDistribution`(전체 분포) 추가 |
| 3차 | §4의 "관계 탭 산점도 6쌍"을 그릴 **점 데이터가 스키마 어디에도 없음.** 결과 JSON은 원본 행을 담지 않으므로([`data-model.md §3.2`](./data-model.md)) 집계만으로는 산점도가 계산 불가능함 | `correlations[].points`(상위 쌍 다운샘플) 추가 + §4에 쌍당 점 수 상한 행 추가 |

네 결함 모두 **규칙은 그럴듯하지만 계산이 불가능한** 유형이었음. 문장으로는 드러나지 않고 지표 → 필드 대조에서만 드러남. 3차는 표현 레이어 구현에 착수하고 나서야 드러났는데, **"화면에 무엇을 그리는가"도 지표 대조 대상**이라는 뜻임 — 통계 지표만 대조하면 놓침.

## 4. 표시 개수 상한

열이 많아도 화면이 무너지지 않게 하는 규칙임 (G2 정보 과부하 대응).

| 대상 | 상한 | 초과 시 |
|---|---|---|
| 발견 목록 (기본 표시) | 15건 | 심각도·영향 열 수 순으로 정렬해 상위만. `전체 보기`로 펼침 |
| 같은 유형의 Finding | 유형당 5건 | "그 외 N개 열에서 동일 발견" 으로 묶음 |
| 변수별 탭의 초기 차트 | 8개 열 | 나머지는 열 목록에서 선택 |
| 관계 탭의 산점도 | 6쌍 | 상관 절댓값 상위만 |
| 산점도 점 수 | 쌍당 200점 | 초과 시 균등 간격 다운샘플 (`correlations[].points`, [`data-model.md §3.6`](./data-model.md)) |
| 상관 히트맵 | 열 20개 | 초과 시 분산 상위 20열로 축소하고 축소 사실을 표시 |

**같은 유형 묶기가 중요함**: 열 50개 중 30개에 결측이 있으면 `F-MISSING-HIGH`가 30건 생성됨. 묶지 않으면 발견 목록이 그 유형으로만 채워져 다른 발견이 묻힘.

## 5. 문구 템플릿 작성 규칙

### 5.1 3단 구성

| 슬롯 | 내용 | 예 |
|---|---|---|
| `what` | 이 데이터의 수치를 넣은 사실 진술 | `age 열의 결측이 32.1%입니다.` |
| `why` | 그것이 문제가 되는 이유 | `평균으로 채우면 분포가 실제보다 좁아지고, 이 열은 오른쪽으로 치우쳐 있어 왜곡이 커집니다.` |
| `how` | 다음에 할 수 있는 일 | `결측 여부를 별도 변수로 만들거나, 해당 행을 제외한 결과와 비교해 보세요.` |

### 5.2 해설 본문과 문장을 공유하지 않음

**안티패턴 #4(템플릿 문장 반복) 회피의 핵심 규칙임.** Finding 문구와 해설 페이지는 같은 지식을 다루지만 역할이 다름.

| | Finding 문구 | 해설 페이지 |
|---|---|---|
| 대상 | **이 데이터** | 개념 일반 |
| 성격 | 수치가 들어간 진단문 | 판단 기준을 갖춘 설명문 |
| 길이 | 3~4문장 | 800자 이상 |

해설 본문을 Finding 문구로 복사하면 색인된 해설 페이지와 문장이 겹치고, 여러 Finding이 같은 문장을 갖게 되어 사이트 내부에서 재포장 패턴이 재현됨.

### 5.3 금지 표현

| 금지 | 이유 |
|---|---|
| `반드시 제거하세요`, `~해야 합니다` | 도메인 맥락을 모르는 상태의 단정. `검토해 보세요` 수준으로 씀 |
| `문제가 심각합니다` 류의 정도 부사 | 심각도는 `severity` 필드와 화면 표기가 담당함 |
| 수치 없는 진술 | `what`에는 항상 실제 수치가 들어감. 수치가 없으면 규칙이 잘못 설계된 것 |

### 5.4 수치 뒤 조사

값에 따라 조사가 달라지는 자리에는 `lib/format.js`의 `ro()`를 씀 — `왜도가 3로`처럼 어긋난 표기는 한국어 우선(차별화 축 5)이라는 주장을 스스로 약화시킴.

| 표기 | 조사 | 근거 |
|---|---|---|
| 숫자로 끝남 (`stat`·`count`) | `ro()` 판정 | 읽었을 때 받침이 있는 영·삼·육(0·3·6)만 `으로` |
| 단위 기호로 끝남 (`percent`·`bytes`) | 항상 `로` | `100.0%` = "백 퍼센트" — 숫자가 아니라 단위를 읽으므로 받침이 없음 |

## 6. 임계값 근거와 미확정 항목

### 6.1 관례적 기준 (출처 있음)

| 임계값 | 근거 |
|---|---|
| VIF ≥ 10 | 다중공선성 판정의 통용 기준 |
| IQR 1.5배 | 박스플롯 이상치 정의 |
| 상관 절댓값 ≥ 0.8 | 다중공선성 경고의 통용 기준 |
| 초과첨도 ≥ 7 | 과도한 첨정(leptokurtic) 판정에 흔히 쓰이는 값 |

### 6.2 자체 판단 (실측 후 조정 대상)

아래는 관례가 아니라 이 프로젝트의 판단임. **샘플 데이터로 실측한 뒤 조정함.**

| 임계값 | 초기값 | 조정 사유가 될 상황 |
|---|---|---|
| 결측 high 기준 | 20% | 실제 데이터에서 너무 자주/드물게 발생하면 |
| 상수 열 판정 | 최빈값 95% | 준상수를 어디까지 볼지 |
| 고카디널리티 | 고유값 50 & 비율 50% | 행 수가 적은 데이터에서 오탐 |
| ID 열 판정 | 고유값 비율 99% | |
| 왜도 경고 | 절댓값 2 | 1.5가 적절할 수 있음 |
| 스케일 차이 | 표준편차 비 100 | |
| Health Score 감점 계수 | §2.1 | 총점 분포가 한쪽으로 몰리면 |
| 타입 추론 다수결 | 비결측 값의 90% | 혼입 값이 많은 실데이터에서 타입을 놓치면 |
| 텍스트 타입 경계 | 고유값 비율 50% & 평균 길이 20자 | 서술형 답변·주소 열의 분류 오판 시 |
| ID 타입 최대 평균 길이 | 36자 (UUID 포함) | 더 긴 식별자 체계가 text 로 새면 |
| ID 타입 최대 공백 포함 비율 | 10% | 공백이 있는 식별자 체계가 실제로 나타나면 |

타입 추론 5종의 상수는 `js/domain/thresholds.js`의 `INFER`임. ID 타입 판정의 고유값 비율은 `F-ID-COL`과 같은 값(99%)을 공유함.

**ID 판정에 공백 신호를 함께 보는 이유**: 고유값 비율과 길이만 보면 `비고 3, 이상 없음` 같은 **짧은 자유 텍스트**가 전부 고유하다는 이유로 `id`로 잡히고 `F-ID-COL` 오탐을 낳음(2026-08-17 통합 스모크에서 실측). 식별자에는 공백이 없다는 것이 길이보다 강한 신호임.

**선행 0이 붙은 값은 수치로 보지 않음**: `06236`(우편번호)·`007`(코드값)은 수치 변환 시 선행 0이 **비가역으로** 사라짐. 기본값을 문자열 유지로 두고, 진짜 수치였다면 사용자가 `numeric`으로 되돌리게 함(UC-02) — 반대 방향은 복구가 불가능하므로 안전한 쪽을 기본값으로 둠. `parse.js`와 `infer.js`가 같은 판정(`hasLeadingZero`)을 공유함.
